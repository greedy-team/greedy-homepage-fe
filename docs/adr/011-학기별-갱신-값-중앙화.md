# ADR 011. 학기마다 갱신하는 값은 site.ts로 모으고, 나머지는 체크리스트로 안내한다

- 상태: 확정 (2026-08)
- 결정자: 4기 홈페이지 TF

## 맥락

이 사이트에는 학기마다 사람이 직접 갱신해야 하는 값이 여러 개 있어요. 지금 진행 중인 기수 번호, 메인 통계(누적 멤버 수·트랙·팀 프로젝트 수), 모집이 열릴 때 채우는 구글폼 주소 같은 거예요.

이런 값 하나가 화면 여러 곳에 각자 따로 쓰여 있으면, 학기가 바뀔 때 어디를 고쳐야 하는지 코드를 다 뒤져야 하고 하나라도 빠뜨리면 화면끼리 어긋나요(예: 모집 배지는 5기인데 통계는 4기).

반면 스터디 커리큘럼 문구나 새로 추가되는 팀 프로젝트처럼, 값 하나로 못 묶고 매번 새 콘텐츠를 통으로 써넣어야 하는 것들도 있어요. 이런 것까지 상수로 만들려 하면 오히려 억지스러워요.

## 결정

**값 하나로 정리되는 것**은 `src/shared/config/site.ts`에 상수로 모아요.

| 상수 | 무엇을 바꾸나 |
| --- | --- |
| `CURRENT_GENERATION` | `RECRUITING_COHORT`, `STATS`의 "진행 기수", `entities/project`·`entities/member`의 `COHORTS` 필터, 멤버 상세의 완료 기수 판별 |
| `TOTAL_MEMBER_COUNT` | `STATS`의 "누적 멤버" |
| `TRACKS` | `STATS`의 "트랙" |
| `TEAM_PROJECT_COUNT` | `STATS`의 "팀 프로젝트" |
| `RECRUIT_FORM_URL` / `APPLY_FORM_URL` | 모집 알림·지원 버튼이 여는 구글폼 주소 (ADR 004) |

**값 하나로 못 묶는 것**(콘텐츠, 또는 백엔드가 소유할 데이터)은 상수화하지 않고, 아래 체크리스트에 위치만 안내해요.

## 학기 시작 체크리스트

1. `src/shared/config/site.ts`의 `CURRENT_GENERATION`, `TOTAL_MEMBER_COUNT`, `TRACKS`, `TEAM_PROJECT_COUNT` 갱신
2. 모집이 열리면 같은 파일의 `RECRUIT_FORM_URL`, `APPLY_FORM_URL`, `IS_RECRUITING` 갱신 (ADR 004)
3. `src/app/study/_sections/content.ts`의 커리큘럼 문구를 새 기수 기준으로 갱신 — 값 하나가 아니라 콘텐츠라 여기서 직접 고쳐요
4. `src/entities/project/api.ts`의 `PROJECTS`에 새 팀 프로젝트 추가 — 아직 백엔드 연동 전까지는 여기서 직접 관리해요 (ADR 002)

## 이유

- 흩어 놓으면 인수인계 때 하나쯤 놓치기 쉬워요. 값 하나면 놓칠 수가 없어요.
- `IS_RECRUITING`(ADR 004)과 같은 패턴이에요. 사이트 전역에서 자주 바뀌는 값은 `shared/config/site.ts`에 모아 단일 지점에서 관리해요.
- 콘텐츠(커리큘럼 문구)나 백엔드가 앞으로 소유할 데이터(팀 프로젝트 목록)까지 억지로 상수 하나로 묶으면, 정작 그 값을 채워 넣는 사람은 결국 콘텐츠 위치로 가야 해서 상수화의 이득이 없어요. 대신 체크리스트에 경로만 안내해요.

## 결과

- 학기가 바뀔 때 확인하는 목록: 위 체크리스트 4단계. 코드를 뒤지지 않고 이 ADR만 보고 시작할 수 있어요.
- 값을 바꾼 뒤엔 프로젝트/멤버 목록의 기수 필터, 메인 통계, 모집 배지, 멤버 상세를 한 번씩 눈으로 확인해요.
