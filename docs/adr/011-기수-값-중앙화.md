# ADR 011. 현재 기수 값은 CURRENT_GENERATION 하나로 관리한다

- 상태: 확정 (2026-08)
- 결정자: 4기 홈페이지 TF

## 맥락

"지금 몇 기가 진행 중인지"를 나타내는 값이 여러 파일에 따로따로 있었어요. 모집 배지 문구(`RECRUITING_COHORT`), 메인 통계(`STATS`의 "진행 기수"), 프로젝트/멤버 목록의 기수 필터(`COHORTS`), 멤버 상세에서 완료된 프로젝트만 골라내는 기준값까지 다섯 곳이었어요.

기수는 매 학기 바뀌는 값이라, 다음 기수를 이어받는 사람이 이 다섯 곳을 전부 찾아 손으로 맞춰야 했어요. 코드를 처음 보는 사람 입장에서는 어디를 고쳐야 하는지 알기 어렵고, 하나라도 빠뜨리면 화면끼리 기수 표시가 어긋나요(예: 모집 배지는 5기인데 통계는 여전히 3기).

## 결정

`src/shared/config/site.ts`의 `CURRENT_GENERATION` 값 하나가 다섯 곳을 같이 바꿔요.

| 위치 | 파생 방식 |
| --- | --- |
| `app/_sections/content.ts`의 `RECRUITING_COHORT` | `CURRENT_GENERATION + 1`기 |
| `app/_sections/content.ts`의 `STATS` "진행 기수" | `CURRENT_GENERATION`기 |
| `entities/project/api.ts`의 `COHORTS` 필터 목록 | `CURRENT_GENERATION + 1`부터 1까지 내림차순 |
| `entities/member/api.ts`의 `COHORTS` 필터 목록 | `CURRENT_GENERATION + 1`부터 1까지 내림차순 |
| `app/members/[id]/page.tsx`의 완료 기수 판별 기준값 | `project.generationNumber !== CURRENT_GENERATION` |

기수가 바뀌면 `CURRENT_GENERATION` 값 하나만 고치면 돼요.

## 이유

- 흩어 놓으면 다음 기수 인수인계 때 하나쯤 놓치기 쉬워요. 값 하나면 놓칠 수가 없어요.
- 모집 예정 기수(`CURRENT_GENERATION + 1`)와 진행 중 기수(`CURRENT_GENERATION`)는 항상 1 차이라는 규칙이 코드에 그대로 드러나요. 문자열로 따로 적어두면 이 관계가 안 보여요.
- `IS_RECRUITING`(ADR 004)과 같은 패턴이에요. 사이트 전역에서 자주 바뀌는 값은 `shared/config/site.ts`에 모아 단일 지점에서 관리해요.

## 결과

- 기수가 바뀔 때 바꾸는 것: `CURRENT_GENERATION` 값 하나. 끝이에요.
- 값을 바꾼 뒤엔 프로젝트/멤버 목록의 기수 필터, 메인 통계, 모집 배지, 멤버 상세를 한 번씩 눈으로 확인해요.
